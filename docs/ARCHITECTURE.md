# Architecture

## 目標

Rustptureの最優先事項は、タスクバーをクリックしてから選択可能になるまでの待ち時間を減らすことです。冷起動を毎回最適化するのではなく、軽いWin32プロセスを常駐させ、必要なウィンドウとGDI資源を事前に準備します。

## プロセス構成

単一プロセス・単一UIスレッドです。バックグラウンドスレッド、ポーリング、タイマーはありません。

- `ControllerWindow`: タスクバーに表示される最小化ウィンドウ
- `OverlayWindow`: 起動時に作成して非表示にしておく範囲選択ウィンドウ
- `PinWindow`: キャプチャごとに作成する画像ウィンドウ

`ControllerWindow` が最小化状態から復元されようとした時、通常の復元を抑止して `OverlayWindow` を表示します。そのため、常駐後のクリック経路ではプロセス作成もウィンドウクラス登録も発生しません。

## 単一起動

既存のコントローラー窓をクラス名で検索します。見つかった場合は独自メッセージを送って、新しく起動したプロセスを終了します。

この方式は名前付き同期物を追加せず、小さな単一ユーザー向けアプリに必要な経路を短く保ちます。

## 画面座標

選択オーバーレイは、次の仮想画面指標から得た物理ピクセル領域を覆います。

- `SM_XVIRTUALSCREEN`
- `SM_YVIRTUALSCREEN`
- `SM_CXVIRTUALSCREEN`
- `SM_CYVIRTUALSCREEN`

左または上側に置かれたモニターの負座標も、そのまま扱います。マニフェストで `PerMonitorV2` を指定し、キャプチャ画像とピン窓の大きさを物理ピクセル単位で維持します。

## 選択描画

オーバーレイは `WS_EX_LAYERED` を持ちます。

- 画面全体: 半透明の黒
- 選択内部: カラーキー色で完全透明
- 選択境界: GDIの枠線

確定時は先にオーバーレイを非表示にし、`DwmFlush` で合成の反映を待ってから `BitBlt` します。選択膜が画像に混ざることを防ぐためです。

## 画像の保持と拡大

元画像は一度作成した `HBITMAP` のまま保持します。拡大・縮小のたびに画像を書き換えず、`WM_PAINT` 内の `StretchBlt` だけで表示します。

これにより、繰り返し縮小・拡大しても元画像が劣化せず、別モニターへ移しても表示対象の範囲が変わりません。

## 資源管理

- `CapturedBitmap` が `HBITMAP` を所有し、`Drop` で解放
- 画面DCと互換DCを小さなRAII型で管理
- オーバーレイのブラシを `OverlayState` が所有
- 各ウィンドウの状態は `GWLP_USERDATA` に置き、`WM_NCDESTROY` で回収
- クリップボードへ渡した成功済みの `HBITMAP` はWindowsへ所有権を移譲

Win32からの再入を考慮し、状態取得は生ポインターで行い、Win32 APIを呼ぶ間に長寿命の `&mut` 参照を保持しない構造にしています。

## 依存関係

実行時依存は `windows-sys` のみです。`embed-resource` はビルド時にマニフェスト、アイコン、バージョン情報を埋め込むためだけに使用します。
